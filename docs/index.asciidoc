=== Pulsar output plugin

include::{include_path}/plugin_header.asciidoc[]

==== Description

Write events to an Apache Pulsar topic. This plugin supports dynamic topic routing,
TLS authentication, token-based authentication, configurable batching, message
compression, retry with exponential backoff, automatic producer reconnection,
and graceful shutdown with in-flight message draining.

Uses Apache Pulsar Client 4.0.9. For broker compatibility, see the
https://pulsar.apache.org/docs/client-libraries/[official Pulsar client compatibility matrix].

[id="plugins-{type}s-{plugin}-serviceUrl"]
===== `serviceUrl`

  * Value type is <<string,string>>
  * Default value is `"pulsar://localhost:6650"`

The Pulsar service URL. Use `pulsar://` for plain connections or `pulsar+ssl://` for TLS.

[id="plugins-{type}s-{plugin}-topic"]
===== `topic`

  * Value type is <<string,string>>
  * This is a required setting

The Pulsar topic to publish to. Supports Logstash `sprintf` format for dynamic topic routing
(e.g., `persistent://public/default/%{topic_name}`).

[id="plugins-{type}s-{plugin}-producer_name"]
===== `producer_name`

  * Value type is <<string,string>>
  * Default value is `"logstash-pulsar"`

Base name for the Pulsar producer. A UUID suffix is appended to ensure uniqueness.

[id="plugins-{type}s-{plugin}-compression_type"]
===== `compression_type`

  * Value type is <<string,string>>
  * Default value is `"NONE"`

Message compression type. Valid values: `NONE`, `LZ4`, `ZLIB`, `ZSTD`, `SNAPPY`.

[id="plugins-{type}s-{plugin}-block_if_queue_full"]
===== `block_if_queue_full`

  * Value type is <<boolean,boolean>>
  * Default value is `true`

Whether `sendAsync` blocks when the outgoing message queue is full.
When `true`, the producer blocks instead of failing immediately.

[id="plugins-{type}s-{plugin}-enable_batching"]
===== `enable_batching`

  * Value type is <<boolean,boolean>>
  * Default value is `true`

Whether to enable message batching. Batching improves throughput at the cost of
slight latency increase.

[id="plugins-{type}s-{plugin}-send_timeout_ms"]
===== `send_timeout_ms`

  * Value type is <<string,string>> (parsed as number)
  * Default value is `"30000"`

Send timeout in milliseconds. If a message is not acknowledged by the broker within
this time, the send fails. Prevents indefinite blocking that can cause deadlocks.

[id="plugins-{type}s-{plugin}-max_pending_messages"]
===== `max_pending_messages`

  * Value type is <<string,string>> (parsed as number)
  * Default value is `"1000"`

Maximum number of pending messages allowed in the producer's outgoing queue.

[id="plugins-{type}s-{plugin}-max_retries"]
===== `max_retries`

  * Value type is <<string,string>> (parsed as number)
  * Default value is `"3"`

Maximum number of retry attempts for failed message sends. Uses exponential backoff
between retries.

[id="plugins-{type}s-{plugin}-retry_initial_delay_ms"]
===== `retry_initial_delay_ms`

  * Value type is <<string,string>> (parsed as number)
  * Default value is `"100"`

Initial delay in milliseconds before the first retry. Subsequent retries use
exponential backoff (delay doubles each attempt) with 25% jitter.

[id="plugins-{type}s-{plugin}-retry_max_delay_ms"]
===== `retry_max_delay_ms`

  * Value type is <<string,string>> (parsed as number)
  * Default value is `"10000"`

Maximum delay in milliseconds between retries. The exponential backoff is capped
at this value.

[id="plugins-{type}s-{plugin}-drain_timeout_ms"]
===== `drain_timeout_ms`

  * Value type is <<string,string>> (parsed as number)
  * Default value is `"30000"`

Maximum time in milliseconds to wait for in-flight async messages to complete
during shutdown. After this timeout, the plugin proceeds with closing producers
even if messages are still in-flight.

[id="plugins-{type}s-{plugin}-enable_tls"]
===== `enable_tls`

  * Value type is <<boolean,boolean>>
  * Default value is `false`

Enable TLS keystore-based authentication. Cannot be used together with `enable_token`.

[id="plugins-{type}s-{plugin}-tls_trust_store_path"]
===== `tls_trust_store_path`

  * Value type is <<string,string>>
  * Default value is `""`

Path to the JKS trust store file. Required when `enable_tls` is `true`.

[id="plugins-{type}s-{plugin}-tls_trust_store_password"]
===== `tls_trust_store_password`

  * Value type is <<string,string>>
  * Default value is `""`

Password for the JKS trust store.

[id="plugins-{type}s-{plugin}-enable_tls_hostname_verification"]
===== `enable_tls_hostname_verification`

  * Value type is <<boolean,boolean>>
  * Default value is `false`

Whether to verify the broker's hostname against the TLS certificate.

[id="plugins-{type}s-{plugin}-allow_tls_insecure_connection"]
===== `allow_tls_insecure_connection`

  * Value type is <<boolean,boolean>>
  * Default value is `false`

Allow insecure TLS connections (skip certificate verification). Not recommended for production.

[id="plugins-{type}s-{plugin}-protocols"]
===== `protocols`

  * Value type is <<array,array>>
  * Default value is `["TLSv1.2"]`

List of TLS protocols to allow.

[id="plugins-{type}s-{plugin}-ciphers"]
===== `ciphers`

  * Value type is <<array,array>>
  * Default value includes `TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256`, `TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384`, `TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256`, `TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384`

List of TLS cipher suites to allow.

[id="plugins-{type}s-{plugin}-auth_plugin_class_name"]
===== `auth_plugin_class_name`

  * Value type is <<string,string>>
  * Default value is `"org.apache.pulsar.client.impl.auth.AuthenticationKeyStoreTls"`

Fully-qualified class name of the Pulsar authentication plugin.

[id="plugins-{type}s-{plugin}-enable_token"]
===== `enable_token`

  * Value type is <<boolean,boolean>>
  * Default value is `false`

Enable token-based authentication. Cannot be used together with `enable_tls`.

[id="plugins-{type}s-{plugin}-auth_plugin_params_string"]
===== `auth_plugin_params_string`

  * Value type is <<string,string>>
  * Default value is `""`

Authentication parameters string (e.g., `token:your-jwt-token`). Used with token authentication.
